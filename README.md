# РАМКА

Контроль границ работ и дополнительных изменений для независимых digital-специалистов и небольших студий автоматизации. Смета → зафиксированный объём → платные изменения → экономика проекта.

## Что уже работает

- Проекты: цена, внутренняя часовая ставка, плановые и фактические часы, прямые расходы, раунды правок, включённые и исключённые работы.
- Отдельные запросы на изменения: оценка часов и цены, текст для клиента, ручная отметка согласования или отказа.
- Плановая прибыль, маржа и стоимость выполнения несогласованных работ за свой счёт.
- Предложение для клиента с печатью / сохранением в PDF через диалог браузера. Внутренние ставки и маржа в предложение не попадают.
- JSON-резервная копия, импорт с новыми ID, CSV-экономика с экранированием формул.
- Серверная версия: приглашения, вход, изолированные аккаунты, срок доступа, продление и отзыв, контроль конкурирующих изменений, экспорт после окончания доступа.

## Две среды

**GitHub Pages — публичная демонстрация.** Используются вымышленные примеры и localStorage. Это не защищённый платный кабинет. Настоящие данные клиентов здесь вводить не нужно. Демонстрация не синхронизируется с серверной версией автоматически.

**Сервер — приватные кабинеты.** Один и тот же интерфейс работает с API на том же домене. Сервер подставляет режим `server` в HTML, а API защищает все операции с проектами независимо от интерфейса. Продление подписки не может быть выполнено из браузера. Вход и подписка реализованы; сервер ещё нужно развернуть на собственном хостинге.

Один аккаунт, до 100 проектов и 200 изменений на проект. Нет командных ролей, встроенного эквайринга, автосписаний, клиентской электронной подписи, автоматического разбора переписки или ИИ-анализа. Ручное согласование не доказывает юридическое согласие клиента. Цена 990 ₽/месяц — гипотеза пилота, а не проверенная готовность платить.

## Запуск серверной версии

Нужны Linux-сервер с Docker Compose, домен с DNS A-записью на сервер и доступные порты 80/443. Caddy получает сертификат автоматически. Не включайте `RAMKA_DEV` на публичном сервере.

1. Склонировать этот репозиторий.
2. Создать `.env` с единственной строкой `RAMKA_DOMAIN=ваш-домен` (без `https://`).
3. Выполнить `docker compose up -d --build`.
4. Открыть `https://ваш-домен`. Вместо демо появится форма входа по приглашению.

База хранится в постоянном Docker volume `ramka_data`; удаление контейнера её не удаляет. Команда `docker compose down -v` удаляет данные — для обычного обновления её не применять.

### Выдача доступа после вручную подтверждённой оплаты

```sh
docker compose exec app python server/admin.py invite customer@example.com --days 30
```

Команда печатает одноразовое приглашение, привязанное к email. Передайте его только этому покупателю. Код действует 7 дней; срок оплаченного доступа начинается при активации. Пользователь сам задаёт пароль длиной 12–128 символов. Без приглашения регистрация невозможна.

Продление от более поздней даты: текущий срок или сегодняшний день:

```sh
docker compose exec app python server/admin.py extend customer@example.com --days 30
```

Отзыв доступа и сессий:

```sh
docker compose exec app python server/admin.py revoke customer@example.com
```

Восстановление пароля после проверки личности покупателя (ввод скрыт, все сессии отзываются):

```sh
docker compose exec app python server/admin.py reset-password customer@example.com
```

Онлайн-оплата и автоматические webhook продления отсутствуют намеренно: нет выбранного платёжного провайдера и реквизитов продавца. Первые платные пилоты можно обслуживать с ручным подтверждением оплаты и выдачей кода, после развёртывания сервера и подготовки условий продажи.

### Резервная копия сервера

Сделать согласованную SQLite-копию внутри контейнера, затем выгрузить её. Не хранить в GitHub.

```sh
docker compose exec app python -c "import sqlite3; a=sqlite3.connect('/data/ramka.db'); b=sqlite3.connect('/data/backup.db'); a.backup(b); b.close(); a.close()"
docker compose cp app:/data/backup.db ./ramka-backup.db
```

Проверку восстановления выполнять на отдельном тестовом экземпляре. Копия содержит данные аккаунтов и проектов; хранить с ограниченным доступом.

### Локальная разработка и тесты

```sh
RAMKA_DEV=1 RAMKA_DB=./local.db python server/app.py
python -m unittest discover -s server -p 'test_*.py'
node --check app.js
```

Локальная разработка: `http://localhost:8000`, ровно этот origin. Для CLI указать тот же `RAMKA_DB`. Встроенный WSGI-сервер предназначен только для локального запуска; публичный запуск использует Gunicorn за Caddy.

## Безопасность и границы проверки

Пароли PBKDF2-SHA256, одноразовые приглашения и сессии хранятся как хеши. Cookie HttpOnly / Secure / SameSite=Strict, JSON-only mutations с проверкой Origin, лимиты входа по email и адресу, SQL-параметры, проверка входных данных, optimistic revision. У каждого аккаунта своя запись данных. Истёкшая подписка блокирует рабочие API, но сохраняет экспорт.

Интеграционный тест проверяет изоляцию двух аккаунтов, активацию и повтор приглашения, вход и выход, блокировку истёкшего доступа, конфликт версий, Origin, отрицательные значения и экспорт после окончания доступа. Это не независимый аудит безопасности. Docker-развёртывание и настоящий платёжный цикл требуют проверки на выбранном сервере.
